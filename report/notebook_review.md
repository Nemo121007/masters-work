## Цель

Методологически корректное сравнение **разных** моделей обнаружения аномалий. Решения не должны сводить одну
модель к другой; общие для моделей правила (время, точки без оценки, замена отвергнутых точек, подбор порога)
применяются единообразно.

## Порядок работы по модели

1. Разбор проблем модели: список проблем со следствиями, варианты решения, рекомендация.
2. Обсуждение по одному вопросу; каждое решение сразу записывается в «Принятые решения» (с датой; следствия
   помечаются как следствия).
3. Текст markdown-ячейки модели по `report/style.md` → запись в блокнот → проверка в IDE → одобрение.
4. Код по одобренному тексту.
5. Тесты: синтетика с известным ответом (новый `notebooks/checks/verify_<модель>.py`) и ячейка модели
   на `data/test.csv`. Тесты не прошли — остановиться, выяснить причину, спросить с вариантами решения.
   Прошли — описание модели в `report/Отчёт.tex` по md-ячейке (исходник — ячейка) и коммит.
6. Коммит: сообщение на русском, по строке на файл («файл: что сделано»), затем очистка `change.log`.

## Правила

- Правка кода блокнота и `app/` — отдельным решением; правка отчёта — после подтверждения;
  `docs/notes/methods.md` — только после явного подтверждения (по AR, ARIMA, фильтру Калмана ещё не обновлён).
- Выводы блокнота, таблицы и разбор результатов в отчёте — только после прогона на реальных данных
  (на `data/test.csv` — синтетика, выводы о моделях не делаются).
- Полный прогон блокнота — только с разрешения; частичный прогон нужных ячеек для проверки — допустим.
- Тексты: безличный стиль, без «пользователь», «агент», личных местоимений; лаконично; формулы вместо слов;
  термины по глоссарию; формулировка «отдельным решением», не «по команде».
- Ответы: коротко и точно; вопросы — с вариантами и рекомендацией.

## Техника правки блокнота

- Блокнот большой: искать строки `grep -n`, смотреть `sed -n`, заменять диапазоны строк `sed -i` по номерам,
  после каждой правки — `python -m json.tool notebooks/example_model.ipynb > /dev/null`.
- Новый текст ячейки — во временный файл, строки JSON — через `json.dumps(..., ensure_ascii=False)`;
  последняя строка ячейки — без `\n` и без запятой.
- Осторожно: `sed -i "${n}r file"` с пустым `n` вставляет файл после каждой строки (случай 2026-10-30).
- Новый код — по `black` (`line-length = 120`): проверка выгрузкой ячейки во временный `.py` и `black --check`.

## Проверочные скрипты

Запуск из `notebooks/`:

```bash
cd notebooks && MPLBACKEND=Agg PYTHONWARNINGS=ignore ../.venv/bin/python checks/verify_kalman.py
```

Каждый скрипт выполняет нужные ячейки блокнота в памяти (выходы не сохраняются), затем ячейку модели
на `data/test.csv` и проверки на синтетике: совпадение с эталоном (statsmodels, sklearn), восстановление
параметров, первые точки без оценки, совпадающее время, разрыв по времени, одиночный выброс с заменой
и без неё, перезапуск после 180 с отвергнутых точек, траектория с дрейфом и 40 эпизодами аномалий.

- `verify_forecast.py` — AR и ARIMA (18 проверок, все проходят).
- `verify_kalman.py` — фильтр Калмана (9 проверок, все проходят; на синтетике с аномалиями 23 ложных
  срабатывания — принятое свойство модели).
- `verify_gp.py` — скользящий гауссовский процесс (9 проверок проходят; эталон — sklearn с очень широким априорным
  распределением тренда; на синтетике с аномалиями 39 ложных срабатываний — принятые свойства модели).

## Общий каркас в блокноте (реализован)

- Общие константы: `GRID_STEP_SEC` (10 с), `TIME_GAP_SEC` (180 с), `THRESHOLD_LOG_POINTS` (60).
- Точки без оценки: оценка аномальности `NaN`, маска `scored`; `evaluate_test(frame, predicted, scored)`,
  `trajectory_series_pair(..., scored)`; `app/evaluation` — метка `NaN`, покрытие (3 столбца).
- Порог: `threshold_candidates` (180 квантилей + 60 значений в логарифмической шкале) для всех моделей;
  `select_threshold_from_records`; `_threshold_record(..., scored)`.
- Модели с заменой отвергнутых точек — общий шаблон: `<модель>_detect(frame, params, taus)` считает сразу
  все кандидаты порога → `(scores (C, N), rejected (C, N))`; `select_<модель>_threshold`: прогон без замены
  (`tau = inf`) → `threshold_candidates` (+ $\chi^2_{0.999}(2)$ для NIS) → пакетный прогон → записи → выбор.
- `time_segments(frame, mask)` — отрезки по разрывам по времени, из точек с одинаковым временем — первая.
- Модели прогноза AR/ARIMA: `fit_forecast_detector`, `forecast_detect`, `select_forecast_threshold`,
  `forecast_predict`.

Найденные ловушки:

- statsmodels вблизи единичного корня: стационарное начальное состояние даёт правдоподобие 0
  или `LinAlgError` → условное правдоподобие (приближённо диффузное начало, `loglikelihood_burn`),
  оптимизация из двух стартов.
- Оценка $\sigma$ фильтра Калмана уходит к нулю при численном вырождении правдоподобия → нижние границы.
- Квантильная сетка порога не даёт кандидатов в провале двугорбого распределения → логарифмическая шкала.
